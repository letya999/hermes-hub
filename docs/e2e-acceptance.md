# Sequential acceptance registry

The full inventory contains 139 scenarios. The default `--scope core` selects 108 local, agent/channel and credential-free installation scenarios; 31 account-dependent connector scenarios are excluded by the owner’s explicit scope. `--scope all` lists the full inventory. A scenario definition is not evidence of a passing E2E test.

Run from the repository root:

```powershell
go run ./cmd/e2e mock --report C:/private/e2e-mock.json
```

Mock mode runs the existing deterministic boundary tests sequentially with race detection. It does not claim real Hermes/provider/Telegram success. A missing fixture is BLOCKED.

For server-driven real Telegram verification, compile cmd/e2e for Linux, copy it into the running communication-hub container, and run:

```text
/data/e2e-acceptance/runner telegram --principal <configured-principal> --select E2E-064,E2E-066,E2E-081 --report /tmp/e2e-report.json
```

The principal must already be enabled and have a Telegram binding. Credentials come from the existing gateway environment, never command-line flags. Server mode automates text, outgoing voice, files/documents, bounded shell execution, usage, routine management, read-only settings/catalog queries and credential-free installation checks. Reminder/script firing uses the routine API in an isolated task. It checks the durable Bot API delivery receipt and agent session/run metadata. It does not exercise incoming Telegram polling. Other scenarios stay BLOCKED until a functional oracle and safe synthetic resources are implemented. A timeout does not resend a potentially delivered message. Schedule, digest-source and terminal-task cleanup errors fail the case and stop subsequent admission; cleanup cannot be hidden behind a successful delivery.

`mock-server --principal <configured-principal> --select E2E-064,E2E-066` uses the actual communication-hub mock endpoint, real Hermes and the configured model provider. Add E2E-065 to test synthetic OGG upload, gateway-side STT and the agent's reply containing the spoken number. This exercises mock ingress; it does not prove Telegram polling. It checks a captured text reply or voice intent plus actual session/run metadata. Outgoing mock transport captures voice intent without sending Telegram audio; the incoming-voice case uses the configured TTS/STT services. Synthetic mock conversations and receipts remain in the private spool for diagnosis.

The authorized task API creates `/v1/tasks` by name for the authenticated owner, without switching the current task; deletion uses `/v1/tasks/<id>`. It cannot target another owner or override the chat. The gateway remains the only queue writer.

Both server modes automate E2E-010 through E2E-015 through the real agent. Admission first reads actual ToolHub tools/list with the existing token bound to the selected owner, runtime and policy; the gateway administrator token cannot substitute for an agent grant. Each routine fixture has a random ID and a reminder due in 2099. After the agent reply, the runner independently checks creation, update, snooze, pause or deletion through the owner-authenticated hub API. The list case must reveal a random fixture value absent from its prompt. Successful cases delete their own fixture; failed or uncertain agent runs retain it for diagnosis. Clean these retained fixtures only after confirming their jobs are terminal. The runner never changes grants.

Live tests reproduced two production installation bugs. Managed projection excluded enabled owner remote-MCP installations even when the profile allowed self-install; it now applies the same owner/policy/revocation checks as source installs. Pinned Hermes pruned required-only JSON Schema selectors inside the CLI `oneOf`, causing its local validator to reject a valid install; every conditional now declares its selector properties, preserving the exclusive alternatives. The upstream dependency remains unchanged. Existing agents need a tool-schema refresh or restart to pick up this contract update.

Real installation checks also reproduced a supervisor race: the native restart acknowledgement arrived before the process had restarted, allowing admission of a new job during shutdown. The supervisor now holds its acquisition lock through the actual owned-container restart and readiness. Projection notifications acknowledge their durable marker before the notifier deadline, while new acquisitions remain blocked. Regression tests cover busy leases, ownership changes, failed readiness and early acknowledgement; a subsequent real Telegram MCP installation passed. The sequential suite now stops after a failure instead of submitting another potentially conflicting job.

Image verification exposed another production defect: scratch exports converted arbitrary bytes to a JSON string, replacing invalid UTF-8 bytes and corrupting PNGs and other binary outputs. The private executor now transfers create-only exports as bounded base64 and writes the decoded bytes through the same locked, scoped file writer. The public text-write schema is unchanged. Regression tests cover byte equality through JSON, size limits, scope escape, mixed payloads and refusal to overwrite. Real PNG-to-JPEG conversion E2E-028 passed in both modes on the rebuilt image. The oracle checks mock captured attachment bytes and, for Telegram, the delivered receipt plus an independent non-consuming fetch with the completed job envelope. It decodes the JPEG and checks dimensions; staged spool blobs are correctly removed after delivery. Image inspection E2E-020 also passed in both modes. The earlier image attempts failed and were cancelled.

Managed setting-change verification reproduced two additional lifecycle defects: restart did not rematerialize the read-only host config with the saved display overlay, and `/readyz` treated the discovery endpoint as proof of task admission readiness. Host restarts now refresh the effective config before Docker remounts it. Readiness checks the native detailed gateway and API-platform initialization, while accepting non-critical degraded health. Both have regressions. E2E-009 passed in both server modes on rebuilt images: the agent changed one display value, an independent read verified its effective value, and the original override and effective value were restored. The oracle waits through the normal synchronous restart route because a delivery receipt precedes restart completion. Failed settings runs keep a private baseline for recovery; the known failed display fixture was reset, and its unadmitted warm-up reached interrupted status through the normal uncertain deadline without replay.

A subsequent real setting write returned an interrupted-operation response because the private ToolHub executor inherited an immediate-restart environment. Both one-shot and pooled Docker execution now force the existing deferred-restart flag; the post-job gateway boundary owns application of the durable marker. Channel regressions assert that flag. A terminal failed settings test restores its original override automatically, while an uncertain job retains the private baseline and is never blindly replayed.

Image generation/editing oracles require a real decoded delivered image; editing also verifies the source SHA256 through read-only scratch inputs, because text reads deliberately reject PNGs and the delivery API accepts only shallow artifact paths. The first real generation failed at the internal media service with HTTP 401. Secondary rendering now resolves the unique media infrastructure in the same spaces directory and environment, with regressions for rotation, missing auth, ambiguous owners and refusal to override shared auth with an unused local Compose token. The existing secondary deployment was also corrected to `infra: false`, with a private backup. It does not copy provider credentials or fall back to an unrelated token. E2E-030 and E2E-031 passed with the actual provider in both server modes; real Bot API delivery was verified. Only the known terminal failed-generation seed fixtures were cleaned.

ToolHub discovery E2E-050, status E2E-052, credential requirements E2E-053 and diagnostics E2E-060 passed through the actual agent in both server modes. Status is compared with an independent owner-bound read of the synthetic installation; credential requirements must be empty; diagnostics returns only the workload count to the test chat, not logs or identity fields. No account-dependent connector is tested.

Watch/check/digest live oracles use the documented public [HTTPbin UUID endpoint](https://httpbin.org/#/Dynamic_data/get_uuid), without credentials or workspace content. A watcher establishes a quiet first baseline and compares the next real minute tick, rather than injecting a fake baseline. Digests select only their own fixture source and verify its committed cursor; checks compare the creation-time baseline with the subsequent response. The runner verifies durable state, bound receipts and absence of an agent mapping for the firing tick. E2E-083, E2E-084 and E2E-086 passed in both server modes. A separate read-only check confirmed receipt occurrence identities and deletion of the test schedules, including digest sources. An earlier constant-source attempt timed out because the first watcher observation correctly did not notify.

The legacy catalog marks entries as host-managed. Existing manifest activation and unmanaged legacy activation remain available; regressions verify the distinction.
