# Шаблон спецификации

## Задача

Описать наблюдаемую пользовательскую проблему и границу компонента.

## Требования

Каждое требование оформить отдельным R-идентификатором и проверяемым условием.

## Чего не делаем

Явно перечислить соседние функции и security guarantees вне scope.

## Критерии приёмки

Таблица связывает каждый R с существующим executable test и честной границей evidence.
После принятия заморозить spec, добавить baseline hash; изменения требований оформлять новой версией.
