# CHG-0148: Conversational discovery and credential onboarding

## Goal

An explicit repository URL installs that source; a generic service request shows up to five real candidates and installs the user's selection; a prepared match uses its reviewed recipe. Admission collects necessary configuration through the protected form without weakening isolation or claiming tools before a real probe.

## Scope and sequence

1. Repair preflight credential/configuration gates and ignored prepare arguments. Regress the observed Metabase errors, URL inputs, alternative credentials and non-auth crash denial.
2. Verify discovery, exact selection, prepared aliases, supported repository sources and asynchronous facade status. Update the runtime onboarding skill and tests.
3. Rebuild the selected dev services and sequentially exercise Metabase, AppMetrica, DataLens, Metrica, Wildberries, Kaspi Shop, filesystem, Postgres, LinkedIn, Google Analytics and two additional real MCP sources. Record only sanitized outcomes; distinguish no-credential servers and unavailable sources from failures.
4. Run just check and the applicable Docker gate. Re-verify changed docs. Do not submit provider credentials or claim provider access from form readiness.

## Boundaries

Keep the existing owner authorization, source pinning, build isolation, Broker delivery and tool admission checks. No upstream patches, fabricated MCP endpoints, account login or unrelated connection changes. Existing untracked operator artifacts stay untouched.
