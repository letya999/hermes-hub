# CHG-0239: Проверяемый rollover старого audit ToolHub

Дата: 2026-10-31. Ветка: `chore/storage-reliability-integration`.

## Причина

Локальный активный `audit.jsonl` содержит только schema 1, около 181 тысяч
записей и 85 МБ. Новый ограниченный ledger не может принимать записи при
пределе 65 536 записей / 16 МБ. Сырые данные нельзя отбрасывать без
восстановимого архива и явной операторской операции.

## План

1. Добавить offline dry-run с безопасными агрегатами и digest всего исходника.
   Каждая строка проверяется строгой schema 1; schema 2 и незавершённые
   операции отклоняются.
2. Под тем же межпроцессным audit lock повторить проверку digest, создать
   закрытый сжатый архив, проверить его повторным чтением, затем атомарно
   открыть новый ограниченный ledger. При сбое до архива исходник остаётся.
3. Проверить отказ на stale digest, повреждённом файле, symlink и занятом
   lock; проверить новый append и неизменность архивной истории.
4. Применить только к остановленному локальному dev ToolHub, запустить его,
   проверить запись в новый ledger без внешней provider mutation. Обновить
   операторскую документацию, `just check` и локальные контракты.

## Пределы

Операторский архив сохраняет старую историю вне активного лимита. Его нельзя
выдавать как диагностический вывод, удалять по TTL или смешивать с новым
schema-2 журналом. Другие пространства и действующие секреты не меняются.
