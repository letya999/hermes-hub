## Findings and required repairs

### F1 — P1: clean passport-only spaces fail supervisor policy checks

`internal/supervisor/control.go:loadSelected` still requires a regular
`settings.yaml` or `agent.yaml` before calling `ReadEffectiveSpace`.
`currentPolicyVersion` and `authorizeCurrentPolicy` use it. A correctly initialized
space without retired files therefore returns `current settings unavailable`.
Use the published identity/revision boundary directly, retaining confinement and
identity checks. Do not create dummy legacy files to make tests pass.

### F2 — P1: rollback loses the exact profile scope

`cmd/hubctl/space_apply.go:applyConfirm` restores a prior revision using a
`Revision` containing only grants. `internal/migration/rights.go:DeriveSpaceRights`
reads `tools.binding.profile_id` from that argument, gets an empty ID, and
`DeriveRights` then rewrites every active profile of the principal/environment.
`RestoreSpaceRights` also intentionally passes an empty profile ID for first apply.
A failed apply for profile A can overwrite profile B's rights; first-apply failure
can clear them. Restore the exact affected records/binding and preserve unrelated
profiles and concurrent revocations. A grants-only reconstruction is insufficient.
The normal-path profile-isolation tests do not exercise this failure path.

### F3 — P1: the six passports are not yet the sole effective configuration

`internal/stack/hermesconfig.go:MaterializeHermesConfig` still applies
`self-settings.json` in managed mode through `applySelfSettings`;
`internal/agenttools/settings.go:SettingsSet` writes that overlay and schedules a
restart without publishing a passport revision. Compression values can therefore
override the config passport. Route edits through the governed publisher and
remove the independently effective overlay. Classify execution selection,
organization policy and connector configuration by actual authority, not filename;
protected ledgers, secrets, connection state and generated outputs are distinct
from authored agent configuration and must not be indiscriminately deleted.

### F4 — P1: tools passport selection still does not drive ToolHub admission

`space_apply.go`'s `tool-policy` hook is a no-op; rights derivation preserves
`CapabilityProfile.Selections`. `capability_store.go:managedToolsLocked` and
`managedToolLocked` use those stored selections. Publishing include/exclude/scope
changes is not enough to prove actual tools/list and tools/call changed. Produce
and activate the ToolHub projection from the same passport revision, independently
of grant issuance. Verify both removal and addition in an already open session.

### F5 — P1: memory/automation ownership and authorization remain unfinished

Runtime vault mounts were removed but `agenttools/memory_search.go` and
`memory_card.go` still use local `VaultDir`. `HUB_VAULTS_BY_PRINCIPAL` has no
production reader in ToolHub. Communication still owns `routines.NewEngine`,
capture, recall and `nightjob.go`; OpenKnowledge still has direct RW vault access.
The shared `run-scope/current` still lets any concurrent private owner run authorize
another private run. `memory_card` still places truth/merge/forget under
`memory.remember`, without the required exact-edit confirmation contract.
Finish CHG-0284–0287 as the existing plans require. Do not restore a runtime vault
mount as a compatibility fix or claim privacy from mount-only/mock-backend tests.

### F6 — P1: new hosting configuration recreates the wrong service

`passport/consumers.go` marks config.hosting slots/image/runtime as recreate.
`reconcile/reconcile.go:runtimeTarget` has no hosting case and returns hermes-runtime.
The generated hosting/controller config can change while its running service keeps
old configuration. Wire the exact hosting and controller consumers; verify the
real planned targets and resulting loaded configuration, not just registry entries.
Review every newly added field through compile, effective read, render, apply and
running consumer, including deletion/reset and change after startup.

### F7 — P1: apply is serialized but still exposes partial activation

`Revision.Publish` changes current before refreshing config-view file by file;
render, rights and reconcile follow. Reader snapshots are not made atomic by the
CLI lock. A derive failure still only invokes pointer/render rollback; previously
mutated records and already recreated services are not comprehensively restored.
Implement consistent revision activation and bounded recovery, or explicit safe
divergence. Do not call pointer rollback a successful whole-system rollback.

### F8 — P1/P2: migration of tests/callers is incomplete and some proof moved off the live path

- Deleted stack APIs remain referenced by hubctl, migration and supervisor tests;
  these are source compile failures, not Windows security-software failures.
- `TestNativeSkillsToolsetAlwaysDenied` fails on a different refusal text. The
  supplied log ends with an interrupted edit; that proposed change is not on disk.
  The current `saveSpace` helper directly stamps generated docs and returns nil;
  it does NOT run CompileAuthored. Merely asserting it returns a compile error
  would be another incorrect repair.
- `TestDocumentImageProfile` drops the selected FAL configuration and renders the
  CLIProxy default. ImageGen has no corresponding authored field/projection in the
  current six-doc shape. Define the canonical home or explicitly decide removal;
  do not change the expected provider to the accidental default.
- `TestRenderCreatesVaultTree` selects a tool but leaves memory.enabled false.
  Fix its input and preserve an independent test that tool selection alone does
  not enable memory. This failure alone does not prove broken vault initialization.
- `TestRenderAllFeatures` moves browser/timeout checks to an artificial
  `CapabilityMode=""` clone. That does not prove the published managed behavior
  retained those guarantees. `settingsToDocs` is a large test-only serializer;
  `publishManagedDocs` bypasses the real compiler/publisher and stamps dev metadata
  into both env views. Keep low-level fixtures where useful, but require a real
  authored-input path for authority/carry-through acceptance.
- Transcript pipelines such as `go test ... | grep ... | head` report shell exit 0
  even next to FAIL output. Record the actual test exit status; use pipefail or
  capture the original process code. Partial greps are not passing-suite evidence.
