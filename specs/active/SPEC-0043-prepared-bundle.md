# Prepared bundle

The twelve stable discovery IDs are `google-workspace`, `slack`, `telegram`,
`github`, `gitlab`, `atlassian`, `sql`, `txttsql`, `grafana`, `prometheus`,
`datalens` and `careergo`. `sql` resolves to the reviewed DBHub entry; other
prepared entries may remain additional choices. A bundle slot without verified
source, recipe, Broker contract and provider semantics is `blocked`, names the
missing evidence and has no selectable candidate. `prepare_source` with a ready
entry's URL remains the sole generic install start. It never skips protected
credential intake, real MCP admission, owner binding or explicit enablement.

Personal Telegram uses a pinned source from `letya999/telegram-mcp`, distinct
from the Communication Hub Bot API. Broker receives API ID, hash, a user
StringSession and expected numeric user ID only through its protected form.
The account ID is verified before MCP serves, and real `tools/list` follows
protected login because this source connects to MTProto at startup. Runtime
and credentialed preflight use owner-isolated network egress. The prepared
entry exposes the source's read-only tool set, with transcription disabled;
send/reply/delete require separate explicit write authorization. Revocation
cuts Hub access immediately; ending the Telegram device session is a separate
provider action. No Telegram secret, session file, OTP or personal message is
tracked in Git.
